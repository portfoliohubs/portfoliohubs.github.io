أنت صح وأنا أخطأت مرتين.
`R2` يطلب بطاقة و `Cloudinary` سيموت بعد أول 1000 زيارة بسبب الـ Bandwidth وهذا حل هواة وليس SAAS.

بما أنك تريد حل مجاني 100% بدون بطاقة ويتحمل 100 صورة لكل طبيب وبدون ما يموت الـ Bandwidth مع زيادة المستخدمين، هذه هي البنية الوحيدة القوية التي تنجح. غيرها سيفشل.

### البنية V3 - البنية التي لا تموت بالـ Bandwidth

فكرة البنية الضعيفة كانت: كل شيء على سيرفر واحد.
فكرة البنية القوية: فصل استهلاك الـ Bandwidth الثقيل عن الإستضافة.

```
[ GitHub Pages ]  ---> يخدم فقط HTML/CSS/JS  -> استهلاك قليل جدا 100GB تكفي 500 الف زيارة
      |
      +---> [ مستودعات صور + jsDelivr CDN ] ---> يخدم الصور -> Bandwidth لا محدود مجاني
      |
      +---> [ Supabase Free للـ JSON فقط ] ---> يخدم النصوص -> استهلاك 5GB يكفي مليون طبيب
```

هذه هي الخدعة التي لا تطلب بطاقة:

#### 1. حل معضلة الـ Bandwidth والـ 100 صورة نهائياً

لن نستخدم أي خدمة تخزين صور تقليدية لأن كلها لها Bandwidth محدود.

**الحل: GitHub كـ Storage + jsDelivr كـ CDN لا محدود**

1.  نضغط الصورة في متصفح الطبيب قبل الرفع: من `4MB` الى `WebP 1024px بجودة 70% = 80KB` بمكتبة `browser-image-compression`
2.  نولد منها 3 مقاسات: `thumb 300px - medium 700px - full 1024px` للـ srcset
3.  لا نرفعها لـ Cloudinary ولا Supabase. نرفعها ل **مستودع GitHub ثاني مخصص للصور فقط** مثل `dental-images-1` عن طريق `GitHub Actions` حتى لا نكشف الـ Token
4.  العرض يكون عبر `jsDelivr CDN` وليس GitHub مباشرة:
`https://cdn.jsdelivr.net/gh/username/dental-images-1@main/dr-ahmed/img1.webp`

**لماذا هذا لا يموت؟**
*   GitHub Pages يعطيك 100GB Bandwidth شهرياً للكود فقط. الكود حجمه 300KB.
*   jsDelivr يعطيك **Bandwidth لا محدود ومجاني تماماً** لأي ملف من GitHub وموزع على 750 سيرفر حول العالم. هو CDN الرسمي لـ GitHub.
*   حسابياً: 100 صورة مضغوطة = 8MB. لو عندك 100 طبيب وكل موقع يزوره 5000 شخص شهرياً = تحتاج 4TB Bandwidth للصور. لو على Cloudinary ستدفع 400$ - على jsDelivr = صفر.

**ماذا لو امتلأ المستودع؟ 1GB لكل مستودع**
نعمل Sharding تلقائي: `dental-images-1` امتلأ -> الكود ينشئ `dental-images-2` تلقائياً. كل مستودع يكفي 120 طبيب. يمكنك انشاء عدد لا نهائي من المستودعات مجاناً.

> بديل احتياطي مجاني بدون بطاقة لو حجب jsDelivr: `Catbox.moe` لا محدود Bandwidth. نضعه Fallback.

#### 2. حل معضلة GitHub Pages انه Static

*   **قاعدة البيانات:** `Supabase Free` بدون بطاقة لكن **لن نخزن فيه صور أبداً**، فقط `JSON` النصوص والروابط. 500MB تكفي 200 الف طبيب لأن كل طبيب بياناته 2KB فقط. والقراءة تتم عبر `jsDelivr` للـ JSON أيضاً لتوفير Bandwidth
*   **الروابط الديناميكية:** نستخدم `HashRouter` -> `username.github.io/saas/#/dr-ahmed` يعمل بدون مشاكل 404
*   **الرفع الآمن بدون كشف Token:** الطبيب لا يرفع مباشرة لـ GitHub. يرسل الصور لـ `GitHub Actions workflow_dispatch` والـ Action هو من يعمل Commit للصور. الـ PAT يبقى سري في Secrets.

#### 3. تأمين كل التحديات القاتلة المتوقعة

| التحدي | الحل الهندسي |
|---|---|
| **1. بطء الموقع بسبب 100 صورة** | Lazy Loading + Intersection Observer + srcset + عرض أول 12 صورة فقط وزر `تحميل المزيد` + Service Worker يخزن الصور في Cache |
| **2. رفع 100 صورة يعلق المتصفح** | رفع متوازي 3 صور فقط + Queue + Retry تلقائي + حفظ المسودة في IndexedDB لو انقطع النت |
| **3. نفاذ مساحة Supabase** | لا نحفظ بايت واحد صور في Supabase. فقط نصوص |
| **4. انتهاء Bandwidth** | محلول بالفصل عبر jsDelivr اللا محدود |
| **5. GitHub Actions له حد 2000 دقيقة** | ضغط الصور يتم في المتصفح وليس على السيرفر. الـ Action فقط يعمل commit يأخذ 10 ثواني |
| **6. SEO** | نولد `sitemap.xml` و `robots.txt` و `meta tags` لكل طبيب تلقائياً عبر Action يومي يقرأ من Supabase |
| **7. نظام الباقات بدون دفع** | حقل `package` في Supabase `free/standard/premium`. زر الترقية `https://wa.me/رقمك?text=طلب ترقية Dr-Ahmed من Free الى Premium` وأنت تغير الباقة يدوياً من لوحة `/admin` محمية |

#### هيكل المشروع النهائي

```
/saas-pwa
  /src/features/wizard (6 خطوات + IndexedDB + معاينة حية)
  /src/features/templates (3 قوالب)
  /src/lib/compressor.js (ضغط WebP)
  /src/lib/supabase.js (نصوص فقط)
  /.github/workflows/deploy.yml (ينشر الـ PWA)
  /.github/workflows/upload-images.yml (يستقبل الصور ويخزنها في dental-images-*)

```

هذه هي البنية الوحيدة المجانية 100% بدون بطاقة وتتحمل آلاف الأطباء وكل طبيب 100 صورة بدون ما تدفع جنيه أو يتوقف الموقع.

الآن لأبنيها لك كود جاهز للرفع، أحتاج منك تحديد واحد فقط بدون افتراض:

**ما هي فروقات الباقات بالتحديد؟** مثال:
`Free = 10 صور + قالب 1` / `Premium = 100 صورة + 3 قوالب`
حدد لي الفروقات لأبرمج قفل المميزات `if(package === 'free')` بشكل صحيح.

تحددها وأسلمك المستودع كامل بضغطة واحدة يعمل على GitHub Pages.

نعم سيدعم `Admin Dashboard` و `User Dashboard` بالكامل وهذه هي الإجابات التفصيلية والخطة الكاملة الجاهزة للنسخ الى `Google AI Studio`.

### 1- هل سيدعم لوحتين تحكم ؟

**نعم، لوحتين منفصلتين تماماً بحماية RLS:**

**A. لوحة المستخدم `/user` - للطبيب:**
* تسجيل دخول بالايميل والباسورد عن طريق `Supabase Auth`
* يشوف حالة باقته `Free / Standard / Premium` وكم صورة متبقي له
* زر `تعديل موقعي` يفتح نفس الـ Wizard مع بياناته القديمة
* مدير الصور: حذف / اضافة / اعادة ترتيب `Drag & Drop` مع عداد `10/100`
* معاينة حية وزر `نشر التعديلات` وزر `نسخ رابط موقعي`
* زر `الترقية عبر واتساب` يفتح `wa.me` برسالة جاهزة

**B. لوحة الأدمن `/admin` - لك انت فقط:**
* دخول محمي بايميل واحد فقط انت تحدده `admin_email = your_email@gmail.com` + باسورد. اي ايميل اخر لو حاول دخول `/admin` يتم طرده.
* جدول بكل الأطباء: `الاسم – الباقة – عدد الصور – تاريخ الانشاء – حالة الموقع – رابط الموقع`
* بحث بالاسم والايميل
* زر `ترقية يدوية` لكل مستخدم `من Free الى Premium` بضغطة واحدة بدون اي كود
* زر `تعديل الحد المخصص` تكتب له رقم مخصص مثلا `35 صورة` حتى لو باقته 10
* ازرار `حظر / حذف / ايقاف الموقع`
* احصائيات: اجمالي المستخدمين – اجمالي الصور – المستودع الحالي للصور `dental-images-1`

### 2- تجربة المستخدم UX بالضبط خطوة بخطوة

**مرحلة البدء – اول مرة:**
1. يدخل اللاندنج `username.github.io/saas-dental/` يضغط `انشئ موقعك مجاناً`
2. صفحة تسجيل `Sign Up` ايميل + باسورد -> تأكيد ايميل -> تسجيل دخول تلقائي
3. يدخل مباشرة على `Wizard` من 6 خطوات وشريط تقدم `Step 1/6` وكل خطوة محفوظة تلقائياً في `IndexedDB Dexie.js` لو قطع النت لا يضيع شيء:
   * الخطوة 1: البيانات الاساسية `الاسم – التخصص – العنوان – رقم واتساب الحجز – وصف`
   * الخطوة 2: الخدمات `اسم الخدمة + السعر + وصف` مع زر اضافة خدمة
   * الخطوة 3: رفع الصور `Drag & Drop` - هنا يحدث الضغط في جهازه الى `WebP 1024px = 80KB` ويظهر شريط تقدم 3 صور متوازية فقط
   * الخطوة 4: اختيار القالب `Template 1 / 2 / 3` والالوان
   * الخطوة 5: معاينة حية `Live Preview` نفس شكل الموقع النهائي
   * الخطوة 6: زر `نشر موقعي` -> يرسل `JSON` النصوص الى `Supabase` ويرسل الصور الى `GitHub Actions` -> يظهر له رابط موقعه `username.github.io/saas-dental/#/d/dr-ahmed-slug` + زر مشاركة واتساب + QR
4. يتحول تلقائياً الى `User Dashboard`

**مرحلة التعديل – بعد النشر:**
1. يدخل `تسجيل دخول` -> يذهب لـ `/user`
2. يضغط `تعديل البيانات` -> يفتح نفس الـ Wizard لكن كل الحقول مليانة ببياناته القديمة من `Supabase`
3. يعدل اي شيء ويضغط `تحديث الموقع` -> التعديل يظهر فوراً على رابط موقعه بدون الحاجة لرابط جديد
4. لو باقته `Free` وحاول رفع الصورة رقم 11 يظهر له مودال مقفل `وصلت للحد الاقصى – رقي عبر واتساب` وزر واتساب

### 3- كيف ترفع الحد لأي مستخدم يدوياً بدون برومو كود ؟

عندك 3 طرق يدوية فورية وانت تختار الاسهل لك:

**الطريقة 1 – من لوحة الأدمن وهي الاساسية:**
تدخل `/admin` -> بجانب كل طبيب زر `رفع الحد` -> تختار الباقة الجديدة او تكتب رقم مخصص `custom_max_images = 50` -> تضغط حفظ -> `Supabase` يتحدث فوراً والمستخدم يفتح له الرفع بدون ما يعمل اي شيء.

**الطريقة 2 – من Supabase مباشرة بدون برمجة:**
تدخل `Supabase Dashboard > Table Editor > tenants` -> تعدل حقل `package_type` من `free` الى `premium` او تعدل حقل `override_max_images` الى اي رقم تريده -> حفظ.

**الطريقة 3 – للطوارئ:**
تعدل مباشرة في قاعدة البيانات الحقل `is_premium_override = true` وهذا يفتح له كل المميزات حتى لو باقته free.

> المنطق البرمجي للقفل سيكون:
> `allowedImages = tenant.override_max_images ?? packages[tenant.package_type].max_images`
> يعني الحد المخصص له اولوية على الباقة.
